# F8 — Instalador, releases e atualizações Implementation Plan

> Executar inline, em uma frente incremental separada. Não publicar uma versão real sem uma tag
> criada pelo mantenedor.

**Goal:** Gerar instaladores Windows, macOS e Linux ao criar uma tag `v*`, publicar a página de
releases e oferecer um caminho de atualização confiável.

**Diagnóstico confirmado:** `electron-builder.yml` já define NSIS no Windows, DMG no macOS e
AppImage no Linux. Não existe workflow de release nem dependência `electron-updater`; o banner
`OutdatedBanner` verifica atualizações de projetos Git e não do aplicativo. O CI já usa pnpm 10,
Node 22 e uma matriz dos três sistemas.

**Compatibilidade pesquisada:** a documentação oficial da versão 26 do electron-builder lista
NSIS, DMG e AppImage como alvos compatíveis com `electron-updater`; o alvo macOS também precisa
produzir ZIP para atualizar pelo Squirrel.Mac. A documentação registra que o auto-update do
macOS exige assinatura de código. A matriz por sistema com `electron-builder --publish always`
está documentada pelo próprio projeto.

**Limites desta sessão:** o worktree não tem pnpm/corepack nem `electron-updater` instalado; o
acesso npm do shell não respondeu. Portanto a dependência e o código de auto-update não podem ser
incluídos ou validados com o lockfile congelado nesta sessão. Esta parte fica explicitamente
pendente; não enfraquecer o CI nem inventar entradas no lockfile.

## Plano

1. Criar `.github/workflows/release.yml`, acionado por tags `v*`, com `contents: write`, instalação
   reproduzível via pnpm 10 e jobs Windows/macOS/Linux que publicam a mesma release GitHub.
2. Garantir que a tag corresponde à versão do `package.json` antes de publicar.
3. Gerar NSIS no Windows, DMG e ZIP no macOS, AppImage no Linux e os metadados de atualização do
   electron-builder.
4. Configurar o provider GitHub com o repositório público conhecido `Cazubii/Glibrary`.
5. Adicionar botão Baixar no topo do README e explicar os avisos de assinatura no Windows/macOS.
6. Adicionar dependência compatível de `electron-updater`, service no main, IPC tipado/validado,
   aviso acessível no renderer, tratamento de progresso/erro e ação explícita para reiniciar e
   instalar. Só concluir esta etapa após pnpm atualizar o lockfile e CI validar os três sistemas.
7. Registrar assinatura macOS/Windows como decisão pendente do mantenedor; não criar certificados,
   credenciais ou secrets.
