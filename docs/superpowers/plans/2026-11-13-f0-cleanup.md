## Tarefa 0: Investigar os testes antes da F0 (concluída)

**Arquivos:**

- Conferir: `tests/agent-presets.test.ts`
- Conferir: `tests/agent-run-manager.test.ts`
- Conferir: `tests/tool-manager.test.ts`

- [x] **Passo 1: Incluir o preset OpenCode que já existe no produto**

Falha investigada: `tests/agent-presets.test.ts` esperava uma lista sem OpenCode, embora o preset já existisse no catálogo:

```ts
expect(commands).toEqual(['claude', 'opencode', 'codex', 'gemini', 'aider']);
```

O preset `opencode` foi adicionado ao catálogo em `fd3081f`, sem atualização da expectativa criada em `e86d882`. A expectativa foi alinhada e essa correção já está no `main` atual.

- [x] **Passo 2: Tornar explícito o provider que os testes do manager exercitam**

Três casos em `tests/agent-run-manager.test.ts` usavam o valor padrão `auto`, que identifica `claude` como `claude-code`, embora verificassem o fluxo genérico. O fixture passou a definir `monitorProvider: 'generic'`; essa correção já está no `main` atual:

```ts
const profile = await store.addAgentProfile({
  name: 'Claude', repoId: 'repo1', command: 'claude', monitorProvider: 'generic'
});
```

Os três testes verificam logs, saída e `lastError` do fluxo genérico. Sem valor explícito, o schema usa `auto`, que identifica o comando `claude` como `claude-code` e suprime a saída bruta em favor do monitoramento local.

- [x] **Passo 3: Comparar o caminho com a forma serializada no script**

Em `tests/tool-manager.test.ts`, substituir a asserção de substring do caminho cru pela asserção do literal JavaScript completo:

```ts
expect(installCall?.args?.[1]).toContain(
  `const targetDir = ${JSON.stringify(join(toolsRoot, 'habblaud'))};`
);
```

`buildHabblaudInstallScript` insere `targetDir` via `JSON.stringify`, que escapa barras invertidas no Windows corretamente. Essa correção já está no `main` atual.

- [x] **Passo 4: Reproduzir os três arquivos após o ajuste**

Executar no diretório `Glibrary`:

```powershell

```

Resultado registrado antes da F0: os 16 testes focados passaram e a suíte completa passou com 268/268 testes. Desde então o PR #2 integrou os ajustes ao `main` e também corrigiu a identidade Git de um fixture; a CI do PR deve validar o estado atual em Linux, Windows e macOS.
